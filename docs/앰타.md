# 앰타

!!! abstract "개요"
    **앰타**(Amta)는 [세준](세준.md)이 2026년에 만들어 운영 중인 AI 캐릭터 채팅
    플랫폼이다. 사용자가 직접 캐릭터를 만들어 공개하고, 다른 사람이 만든 캐릭터와
    대화할 수 있다. 표어는 *"상상이 현실이 되는 채팅"*.
    Next.js와 MongoDB, Google Gemini API로 만들었고 Vercel에 올라가 있다.[^site]

[^site]: [emta-ai.vercel.app](https://emta-ai.vercel.app)

## 1. 개요

AI 캐릭터와 대화하는 서비스다. 캐릭터를 **만드는 쪽**과 **대화하는 쪽**이 모두 있는
양면 서비스라, 로그인·데이터베이스·외부 AI API·권한 관리가 한 번에 필요했다.

[한랭](한랭.md)이 밑바닥(컴파일러, 어셈블리)을 다뤘다면 이쪽은 반대편,
웹 서비스 전체를 한 바퀴 도는 작업이었다.

저장소 이름은 `zeta-clone` 인데, 처음에 비슷한 서비스를 따라 만들어 보며
시작했기 때문이다. 만들면서 로어북·랭킹·전역 설정 같은 것들이 붙어
지금은 **앰타**라는 이름으로 따로 굴러가고 있다.

## 2. 기술 스택

| 분류 | 쓴 것 |
|------|-------|
| 프레임워크 | Next.js 14 (App Router) |
| 언어 | TypeScript |
| 데이터베이스 | MongoDB Atlas (Mongoose) |
| AI | Google Gemini API (`gemini-2.5-flash-lite`) |
| 인증 | NextAuth.js (이메일/비밀번호 + Google OAuth) |
| 스타일 | Tailwind CSS |
| 배포 | Vercel |

소스는 `src/` 아래 약 4,000줄이다.

## 3. 기능

화면은 홈 · 캐릭터 · 랭킹 · 로어북으로 나뉜다.

### 3.1. 캐릭터

사용자가 캐릭터를 만들어 공개할 수 있다. 캐릭터에는 이름, 설명,
**시스템 프롬프트**, 첫 인사말, 아바타, 태그, 장르가 붙는다.
시스템 프롬프트가 그 캐릭터의 성격과 말투를 결정한다.

만든 캐릭터는 인기순·최신순으로 볼 수 있고 장르와 검색으로 거를 수 있다.
좋아요를 누를 수 있으며 랭킹 페이지가 따로 있다.
자기가 만든 캐릭터는 수정·삭제할 수 있다.

### 3.2. 채팅

캐릭터를 골라 대화한다. 대화 내용은 MongoDB에 남아서 나갔다 들어와도 이어진다.
응답은 **스트리밍**으로 한 글자씩 나온다.

채팅 화면에는 몇 가지 손을 본 부분이 있다.

- `*행동*` 처럼 별표로 감싼 부분은 회색 기울임으로 보여 준다.
  캐릭터 채팅에서 행동 묘사를 구분하는 관습을 따른 것이다.
- 입력창에 별표를 한 번에 감싸 주는 버튼을 달았다.
- 마음에 안 드는 답은 다시 생성할 수 있다.

### 3.3. 로어북

이 프로젝트에서 가장 손이 많이 간 기능이고, 따로 메뉴까지 있다.

캐릭터 하나에 세계관 설정을 잔뜩 넣으면 시스템 프롬프트가 너무 길어진다.
**로어북**은 설정을 항목별로 따로 모아 두고 캐릭터에 붙이는 방식이다.
로어북 하나를 여러 캐릭터가 공유할 수 있다.

- 로어북은 여러 개의 **항목**으로 이루어진다. 항목마다 켜고 끌 수 있다.
- 캐릭터를 만들 때 쓸 로어북을 고른다.
- 관리자가 만든 **전역 로어북**은 모든 대화에 자동으로 들어간다.

### 3.4. 이미지 생성

Gemini의 이미지 생성 모델로 캐릭터 아바타를 만들 수 있다.
직접 업로드하는 것도 된다.

### 3.5. 관리자

사용자에게 역할(role)을 두어 관리자를 구분한다.
관리자는 사용자 목록을 보고 관리할 수 있으며, 전역 로어북을 만들 수 있다.

## 4. 데이터 구조

컬렉션 네 개로 이루어진다.

`User`
:   이름, 이메일, 비밀번호(bcrypt 해시), 아바타, 소개, 역할

`Character`
:   이름, 설명, 시스템 프롬프트, 인사말, 아바타, 태그, 장르, 만든 사람,
    대화 수, 좋아요 수, 좋아요 누른 사람들, 붙은 로어북, 공개 여부

`ChatSession`
:   사용자, 캐릭터, 메시지 목록(역할 · 내용 · 시각), 마지막 메시지

`Lorebook`
:   이름, 설명, 만든 사람, 항목들(제목 · 내용 · 사용 여부), 공개 여부, 전역 여부

## 5. 만들면서

### 5.1. 모바일

처음에는 데스크톱만 보고 만들었더니 휴대폰에서 아래쪽 내비게이션이
잘 안 눌렸다. 링크 영역을 칸 전체로 넓혀서 고쳤다.
랭킹으로 가는 길도 모바일에서는 막혀 있어서 따로 뚫었다.

### 5.2. 이미지 생성 모델

Gemini의 이미지 생성 쪽은 모델 이름과 엔드포인트가 자주 바뀌어서
여러 번 고쳤다. 커밋 기록에 그 흔적이 남아 있다.

### 5.3. 스트리밍 오류

스트리밍 응답 중에 오류가 나면 화면에 아무것도 안 나오고 멈춰 버렸다.
오류를 사용자에게 보여 주도록 고치고 Gemini SDK도 올렸다.
