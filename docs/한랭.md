# 한랭

!!! abstract "개요"
    **한랭**(hanlang)은 [세준](세준.md)이 2026년에 만든 교육용 한국어 프로그래밍 언어다.
    확장자는 `.han`. 조사를 문법 요소로 쓰며, 인터프리터가 아니라
    x86-64 네이티브 코드로 컴파일된다. MIT 라이선스로 공개되어 있다.[^repo]

[^repo]: [github.com/sejunch/hanlang](https://github.com/sejunch/hanlang)

## 1. 개요

한국어를 읽듯이 읽히는 것을 목표로 만든 프로그래밍 언어다.
"읽었을 때 뜻이 바로 보이는 것"을 다른 무엇보다 앞에 두었고,
그 대가로 타이핑이 길어지는 것은 감수했다.

```
학생 이란 묶음 {
    이름은 문자.
    점수는 정수.
}

반은 []이다.
반에 (새 학생)을 넣다.
(반의 1번째)의 이름은 "세준"이다.
(반의 1번째)의 점수는 95이다.

만약 (((반의 1번째)의 점수) >= 90) 라면 {
    ((반의 1번째)의 이름)을 끝"(이)가 " 말하다.
    "1등!"이라고 말하다.
}
```

[한글 프로그래밍 언어](한글-프로그래밍-언어.md) 계보에 속한다.

## 2. 특징

### 2.1. 조사가 인자 이름표가 된다

이 언어에서 가장 두드러지는 부분이다. 함수를 정의할 때 쓴 조사가
그대로 호출 규약이 된다.

```
가와 나를 더하다 란 {
    가 + 나를 돌려주다.
}

(3과 4를 더하다)를 말하다.
```

스위프트는 `move(from:to:)` 처럼 인자 라벨을 문법에 따로 만들어 넣었지만,
한국어에는 조사가 이미 있다. 문법이 공짜로 해주는 셈이다.

조사는 모든 연산자보다 우선순위가 낮다. 그래서 `가 + 나를 돌려주다` 는
`(가 + 나)를 돌려주다` 로 읽힌다.

### 2.2. 인터프리터가 아니다

C++로 작성한 컴파일러 한 파일(`hanc.cpp`)이 x86-64 어셈블리(AT&T 문법)를 생성하고
gcc로 링크한다. 별도의 실행 환경 없이 리눅스 실행 파일이 그대로 나온다.

```bash
./hanc 프로그램.han -o 프로그램
./프로그램
```

과거 한글 프로그래밍 언어들이 자체 실행 환경에 묶여 함께 사라진 것과 대비된다.
[한글 프로그래밍 언어](한글-프로그래밍-언어.md#3-왜-대부분-사라졌나) 문서 참고.

### 2.3. 함수가 타입마다 알아서 만들어진다

타입을 적지 않아도 되고, 인자 타입 조합마다 컴파일러가 따로 찍어낸다.
C++ 템플릿의 단형화와 같은 방식이다.

```
가와 나를 더하다 란 { 가 + 나를 돌려주다. }

(3과 4를 더하다)를 말하다.          // 7
(1.5와 2.25를 더하다)를 말하다.      // 3.75
("가"와 "나"를 더하다)를 말하다.     // 가나   같은 함수다
```

덕분에 표준 라이브러리의 `정렬하다` 하나로 정수 목록·소수 목록·문자 목록을
모두 정렬할 수 있다.

### 2.4. 에러 메시지가 핵심 기능

교육용이므로 에러 메시지를 기능으로 취급한다.
한국어로, 소스 줄과 캐럿과 고치는 법까지 함께 출력한다.

```
[오류] 3행: '나이' 는 정수 변수인데 소수를 넣으려 함. 처음부터 소수로 쓰려면 0.0 처럼 만들기
  3 | 나이는 3.5이다.
    | ^^^^
```

함수가 타입마다 따로 만들어지기 때문에 에러가 함수 몸통에서 날 수 있는데,
그럴 때는 **어느 호출 때문에 그 조합이 만들어졌는지**도 같이 알려준다.
C++ 템플릿 에러가 읽기 힘든 문제에 대한 대응이다.

```
[오류] 1행: '*' 는 숫자끼리만 됨
  1 | 수를 두배로 란 { (수 * 2)를 돌려주다. }
    |                      ^
  '두배로' 를 3행에서 부름 (인자: 문자)
```

### 2.5. 표준 라이브러리가 한랭으로 짜여 있다

8개 파일 79개 함수 전부 `.han` 파일이다. 학습자가 열어서 읽을 수 있다.
`lib/정렬.han` 에는 선택·삽입·퀵·병합 정렬이 나란히 들어 있어
알고리즘을 비교해 볼 수 있다.

| 파일 | 내용 |
|------|------|
| `수학.han` | 최대공약수, 소수 판정, 팩토리얼, 자릿수 |
| `목록.han` | 정렬, 찾기, 복사, 이진탐색, 중복 제거 |
| `문자.han` | 자르기, 나누기, 대소문자, 다듬기 |
| `정렬.han` | 선택·삽입·퀵·병합 정렬 |
| `통계.han` | 평균, 중앙값, 최빈값, 분산, 표준편차 |
| `격자.han` | 격자 출력, 복사, 전치, 이웃 세기 |
| `분수.han` | 유리수 사칙연산 |
| `큰수.han` | 자릿수 제한 없는 정수 |

## 3. 문법

전체 문법은 저장소의 `문법.md` 에 정리되어 있다. 여기서는 대표적인 것만 적는다.

### 3.1. 기본

문장은 마침표로 끝나고, 서술어가 뒤에 오는 한국어 어순을 따른다.
받침 검사는 하지 않아서 `를/을`, `는/은`, `와/과` 를 아무렇게나 써도 된다.

```
나이는 17이다.                     // 대입. 첫 대입에서 타입이 정해진다
"안녕"이라고 말하다.                // 출력
이름은 듣다.                       // 입력 (항상 문자를 돌려준다)
만약 (나이 >= 18) 라면 { } 아니면 { }
10번 반복하다 { }
(나이 < 20) 인 동안 { }
```

### 3.2. 타입

정수 · 소수 · 문자 · 목록 · 격자(2차원) · 묶음(구조체) 여섯 가지다.

```
점수는 [85, 90, 100]이다.        // 목록
(점수의 1번째)를 말하다.          // 1부터 센다
점수에 80을 넣다.                // 뒤에 추가
(점수에서 빼다)를 말하다.         // 뒤에서 빼기 — 이 둘로 스택·큐가 된다

판은 3행 4열이다.                // 격자
(판의 2행 3열)을 말하다.

학생 이란 묶음 { 이름은 문자. 점수는 정수. }   // 묶음
철수는 (새 학생)이다.
```

나눗셈은 항상 소수를 준다(`7 / 2 = 3.5`). 학교에서 배우는 나눗셈과 맞추기 위해서다.
몫이 필요하면 `~/` 를 쓴다.[^slash]

[^slash]: `//` 는 주석과 부딪혀서 쓸 수 없었다. 다트(Dart)에서 쓰는 `~/` 를 가져왔다.

### 3.3. 출력 끝맺음

`말하다` 는 기본으로 줄바꿈을 붙인다. 조사와 서술어 사이에 `끝"..."` 을 넣으면
줄바꿈 대신 그 문자로 끝맺는다. `\n` 이 한글이 아니라는 이유로 나온 문법이다.

```
"안녕"을 끝" " 말하다.
"세준"을 말하다.                 // 안녕 세준
```

## 4. 만든 과정

### 4.1. 파이프라인

`렉서 → 불러오기 → 조사 분리기 → 파서 → 타입 검사기 → 코드 생성` 여섯 단계다.
컴파일러 전체가 `hanc.cpp` 한 파일에 들어 있다.

### 4.2. 모든 값을 64비트로 통일

정수는 그대로, 문자는 포인터, 소수는 double 비트 패턴, 목록과 묶음은 포인터로
전부 64비트에 담는다. 덕분에 함수 호출 규약이 타입과 무관하게 하나뿐이다.
나중에 목록·격자·묶음을 추가할 때 호출부를 전혀 건드리지 않아도 됐다.

### 4.3. 조사 분리기

가장 손이 많이 간 부분이다. 렉서 입장에서 `가와` 는 그냥 한글 두 글자라
어디서 끊어야 할지 알 수 없다.

문제는 매개변수 이름이 조사와 겹칠 때 터진다. `가와 나를 더하다` 에서
`가` 는 매개변수이면서 동시에 조사이기도 하다.

해결책은 **아는 이름 목록을 조사 판정보다 먼저 보는 것**이었다.
함수 정의 헤더를 미리 훑어 매개변수를 등록해 두고, 낱말이 들어오면
키워드 → 함수 이름 → **아는 변수** → 조사 → … 순으로 판단한다.

이후에도 비슷한 함정이 계속 나왔다.

- `목록의 가번째는` 에서 `가번째는` 이 통째로 새 변수가 됐다.
  조사를 먼저 벗기고 나서 `번째` 를 확인하도록 고쳤다.
- `행`, `열` 을 무조건 쪼갰더니 `여행`, `배열`, `진행` 이 박살났다.
  어간이 아는 변수일 때만 쪼개도록 제한했다.

### 4.4. 밟은 지뢰

- 소수 리터럴을 자릿수 누적으로 파싱했더니 `0.3` 이 `0.30000000000000004` 로 읽혀
  `0.1 + 0.2 == 0.3` 이 참이 되는 사고가 있었다. 오차가 상쇄되어 겉보기에는
  맞아 보이는 최악의 유형이었다. `strtod` 로 바꿔 해결했다.
- `-5의 절댓값` 이 `-(5의 절댓값)` 으로 읽혀 `-5` 가 나왔다.
  부호만 틀리는 유형이라 특히 위험했다. `-` 바로 뒤가 숫자면 음수 리터럴로
  접도록 고쳤다.
- `strcmp` 의 반환값을 64비트 레지스터 전체로 비교하고 있었다.
  `strcmp` 는 32비트 정수를 돌려주고 위쪽 32비트는 정의되지 않아서,
  운으로 맞고 있던 코드였다.

## 5. 지금 상태

코드는 [Claude](https://claude.ai)와 함께 썼다. 다만 문법 결정은 직접 했다.
몫 연산자 `~/`, 격자의 `3행 4열`, 출력 끝맺음 `끝"..."` 같은 것들이 그렇게 정해졌다.
[세준](세준.md#4-작업-방식) 문서 참고.

| | |
|---|---|
| 컴파일러 | `hanc.cpp` 한 파일, 약 2,700줄 |
| 라이브러리 | 8개 파일 79개 함수 (전부 한랭으로 작성) |
| 테스트 | 60개, `make test` 한 번으로 전부 |
| 공개 | 2026년 7월, MIT 라이선스 |

아직 안 되는 것: 목록 안의 목록(중첩), 묶음 안의 묶음, 파일 입출력, 이름공간.
변수는 단형이라 첫 대입에서 정해진 타입이 끝까지 간다(함수만 다형).

## 6. 써보기

```bash
git clone https://github.com/sejunch/hanlang
cd hanlang
make
./han examples/demo.han
```

설치는 `sudo make install`.
