# 조사를 떼어내는 게 이 언어의 심장이었다

한글 프로그래밍 언어를 만들 때 제일 먼저 부딪히는 문제는 예상과 다른 곳에 있었다.
키워드를 한글로 바꾸는 건 쉽다. **조사가 문제다.**

<!-- more -->

## 왜 어려운가

한랭에서는 조사가 함수 인자의 이름표다.

```
가와 나를 더하다 란 {
    가 + 나를 돌려주다.
}

(3과 4를 더하다)를 말하다.
```

`가와` 는 변수 `가` 와 조사 `와` 로 나뉘어야 한다. 그런데 렉서 입장에서
`가와` 는 그냥 한글 두 글자다. 어디서 끊어야 할지 알 수 없다.

영어라면 공백이 알아서 해준다. `add(a, b)` 에서 `a` 와 `,` 는 다른 글자다.
한국어는 붙여 쓴다. `나이는`, `점수를`, `목록에서` 전부 한 덩어리로 들어온다.

## 첫 번째 함정: 조사처럼 생긴 변수

단순하게 생각하면 "낱말 끝이 조사면 떼면 되겠네" 싶다. 그런데 이게 바로 깨진다.

```
가와 나를 더하다 란 { ... }
```

매개변수 이름이 `가` 인데, `가` 는 조사이기도 하다. `가와` 를 보고
"어? `와` 가 조사네" 하고 떼면 남는 건 `가` — 이건 맞다. 그런데 다른 자리에서
`가` 가 혼자 나오면? 조사로 볼 것인가 변수로 볼 것인가.

## 해결: 심볼 테이블을 보고 판단한다

결국 **아는 이름 목록(`known`)을 먼저 보는 것**으로 풀었다.
낱말이 들어오면 이 순서로 판단한다.

1. 키워드 통짜인가 (`말하다`, `반복하다`)
2. 함수 이름 통짜인가
3. **아는 변수 통짜인가** ← 조사 판정보다 먼저
4. 조사 낱말인가
5. 아는 변수 + 조사인가
6. 키워드 + 조사인가 (`정수로`)
7. …

핵심은 **3번이 4번보다 앞에 있다는 것**이다. 매개변수 `가` 가 이미 등록돼 있으면
조사 판정으로 넘어가기 전에 변수로 확정된다.

그리고 함수 정의 헤더를 미리 훑어서(`prescan`) 매개변수를 먼저 등록해 둔다.
그래야 함수 몸통을 읽을 때 `가` 가 변수인 걸 안다.

## 두 번째 함정: 붙어 있는 의존명사

목록을 넣으면서 새로운 게 터졌다.

```
목록의 가번째는 (목록의 나번째)이다.
```

`가번째는` 이 통째로 새 변수로 등록돼 버렸다. `번째` 를 떼는 규칙은 있었는데,
**조사가 뒤에 더 붙어 있는 경우**를 처리하지 않았던 것이다.
`가번째` 는 `번째` 로 끝나지만 `가번째는` 은 `는` 으로 끝난다.

그래서 조사를 먼저 벗기고 → 그다음 `번째` 를 확인하도록 고쳤다.

## 세 번째 함정: 한 글자짜리는 위험하다

2차원 격자를 넣으면서 `행` 과 `열` 을 쪼개야 했다.

```
표의 행번호행 열번호열은 (행번호 * 열번호)이다.
```

`번째` 처럼 무조건 쪼개면 될 줄 알았는데, 그러면 이런 게 박살난다.

```
여행은 3이다.
배열은 5이다.
진행은 7이다.
```

`여행` 이 `여` + `행` 이 되고 `배열` 이 `배` + `열` 이 된다.
`번째` 는 두 글자라 우연히 겹칠 일이 거의 없지만 한 글자는 다르다.

해결은 **어간이 아는 변수일 때만 쪼개는 것**이다.
`여행` 에서 `여` 는 등록된 변수가 아니니 안 쪼갠다.
`행번호행` 에서 `행번호` 는 이미 있는 변수니 쪼갠다.

## 정리

조사 분리기는 200줄이 안 되는데, 이 언어에서 가장 손이 많이 간 부분이다.
규칙 하나를 넣을 때마다 기존 규칙과 부딪히는 자리를 확인해야 했다.
그래서 컴파일러 인수인계 문서에 **규칙 순서 자체를 통째로 적어뒀다.**
순서가 곧 방어선이기 때문이다.

지금은 이 규칙들이 잘 돌아간다. `여행`, `배열`, `진행` 도 안전하고
`가번째는`, `열번호열은` 도 제대로 쪼개진다. 테스트에 전부 넣어놨다.
