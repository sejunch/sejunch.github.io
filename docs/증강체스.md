# 증강 체스

!!! failure "폐기"
    **더 만들지 않는 프로젝트다.** 미완성 상태에서 멈췄다.
    이 문서는 어디까지 만들어졌는지를 남겨 두려고 쓴 것이다.
    안 된 채로 끝난 것은 [6. 어디까지 갔나](#6-어디까지-갔나) 에 적어 두었다.

!!! abstract "개요"
    **증강 체스**(Augment Chess)는 [세준](세준.md)이 만들다 그만둔 변형 체스 웹 게임이다.
    기물의 움직임을 **Chessembly**라는 언어로 정의하고, 게임 도중 카드를 뽑아
    기물을 바꾸는 **증강** 시스템이 있다. 저장소는 비공개다.

## 1. 개요

보통의 체스가 아니라 **규칙 자체를 바꿔 가며 두는 체스**다.

- 보드 크기가 6×6, 8×8, 10×10 중에서 고를 수 있다.
- 기물의 움직임은 코드로 정의한다. 브라우저 안에서 새 기물을 만들 수 있다.
- 게임 도중 **증강 카드**를 뽑아 자기 기물을 바꾼다.
- 승리 조건은 체크메이트가 아니라 **왕을 실제로 잡는 것**이다.
  체크·체크메이트 개념 자체를 두지 않았다.

[한랭](한랭.md)이 사람이 읽는 언어를 만든 것이라면, 이쪽은
**기물의 움직임을 적는 작은 언어**를 만든 것이다. 결국 같은 종류의 일이다.

## 2. Chessembly

기물이 어떻게 움직이는지를 적는 언어다. en-passant.org의 DSL을 참고해
직접 구현하고 확장했다.

```
# 나이트;
take-move(2, 1);
take-move(2, -1);
take-move(-2, 1);
take-move(-2, -1);
take-move(1, 2);
take-move(1, -2);
take-move(-1, 2);
take-move(-1, -2);
```

```
# 비숍;
take-move(1, 1) repeat(1);
take-move(1, -1) repeat(1);
take-move(-1, 1) repeat(1);
take-move(-1, -1) repeat(1);
```

`repeat` 이 붙으면 그 방향으로 쭉 미끄러진다. 이 한 줄 차이가
도약하는 기물과 미끄러지는 기물을 가른다.

### 2.1. 명령

| 명령 | 뜻 |
|------|-----|
| `move(dx, dy)` | 빈 칸으로만 이동 |
| `take(dx, dy)` | 적이 있을 때만 |
| `take-move(dx, dy)` | 둘 다 (대부분의 기물) |
| `take-jump(dx, dy)` | 넘어가며 잡기 |
| `shift` / `catch` | 이동만 / 포획만 하는 변형 |
| `repeat(n)` | 슬라이드 |
| `# ... ;` | 주석 |

### 2.2. 직접 넣은 확장

원래 스펙에 없는 것들이다.

`tag(royal)`
:   이 기물이 잡히면 그 편이 진다. 왕 말고 다른 기물도 royal로 만들 수 있다.

`tag(immune)`
:   잡히지 않는다.

`.first`
:   첫 수에만 쓸 수 있는 움직임. 폰의 두 칸 전진 같은 것.

`.once`
:   게임 통틀어 한 번만.

`.royal`
:   royal 기물만 잡을 수 있다.

`.swap` + `movement(N){}`
:   수를 둘 때마다 행마가 번갈아 바뀐다.

### 2.3. 손대지 못한 부분

원래 DSL에는 `label` · `jne` · `peek` · `edge-*` · `rip` 같은
**점프와 반복** 명령이 있다. 파서는 이것들을 읽고 무시한다.

의미가 공개된 문서를 구하지 못해서였다.
추측해서 구현하면 진짜 스펙과 어긋나므로 일부러 미뤄 두었고,
그대로 끝났다.

## 3. 기물

표준 여섯 기물 외에 페어리 체스 기물 12종이 들어 있다.

| 기물 | 움직임 |
|------|--------|
| 아마존 | 퀸 + 나이트. 가장 강하다 |
| 챈슬러 | 룩 + 나이트 |
| 아치비숍 | 비숍 + 나이트 |
| 나이트라이더 | 나이트 방향으로 무제한 슬라이드 |
| 페르즈 · 와지르 | 대각 1칸 · 직교 1칸 |
| 다바바 · 알필 | 직교 2칸 도약 · 대각 2칸 도약 |
| 카멜 · 제브라 | (3,1) 도약 · (3,2) 도약 |
| **구행** | 룩처럼 가다가 꺾인다. 규칙이 복잡해 코드로 직접 계산한다 |
| **조커** | 잡히지 않고, 왕만 잡을 수 있다 |

구행과 조커는 직접 만든 기물이다. 특히 조커는 `tag(immune)` 과 `.royal` 을
같이 써서 "죽지 않지만 왕밖에 못 잡는" 기물이 됐다.

### 3.1. 기물 만들기

스튜디오 화면에서 Chessembly를 직접 쓰고 흑·백 아이콘 SVG를 올리면
새 기물이 된다. 로그인하면 데이터베이스에 저장되어 다른 사용자도 쓸 수 있다.

아이콘은 윤곽선만 있는 SVG를 올리면 안쪽을 진영 색으로 자동으로 채운다.
캔버스에 그려 놓고 flood fill 하는 방식이다.

## 4. 증강

게임 도중 카드를 뽑아 판을 바꾸는 장치다.

- 게임 시작할 때와 **N수마다** 3장 중 1장을 고른다.
- 고른 카드는 인벤토리에 쌓인다.
- 자기 차례에 무료 행동으로 쓴다. 카드를 고르고 대상 기물을 클릭한다.

카드는 둘까지 만들었다.

**광대**
:   아군 퀸 하나를 조커로 바꾼다.

**구행**
:   룩 하나를 희생해 아군 퀸을 구행으로 만든다.

커스텀 게임에서 증강을 끄거나, 나오는 간격(4·6·8·10수)을 바꿀 수 있다.

## 5. 기술 스택

| 분류 | 쓴 것 |
|------|-------|
| 프론트 | Vite + React + TypeScript |
| 백엔드 | Express + MongoDB (Mongoose) |
| 인증 | JWT |
| 엔진 | 직접 작성 (`src/variant/engine.ts`) |

체스 라이브러리를 쓰지 않고 엔진을 직접 썼다.
보드 크기가 가변이고 기물이 코드로 정의되기 때문에
기성 라이브러리로는 안 되는 부분이 많았다.

특수 규칙은 표준 체스대로 구현되어 있다.
폰의 두 칸 전진, 앙파상, 캐슬링(가변 보드에서도, 지나가는 칸이 공격받으면 금지),
폰 승격. 기보도 대수기보로 남는다.

## 6. 어디까지 갔나

| | |
|---|---|
| 상태 | **폐기** |
| 코드 | 약 4,500줄, TypeScript |
| 저장소 | 비공개 |

만들어진 것: 싱글(사람 대 사람), 커스텀 게임 구성, 기물 스튜디오, 기물 도감,
로그인과 기물 공유.

끝내 안 한 것

- **AI 상대** — 사람 둘이서만 둘 수 있다. 혼자서는 못 논다
- **멀티플레이** — 버튼만 있고 안쪽은 비어 있다
- **증강 카드가 두 장뿐** — 드래프트와 인벤토리는 다 돌아가는데 카드가 없다
- 게임 룰 설정 화면
- Chessembly의 점프·반복 명령

### 6.1. 왜 접었나

흥미가 떨어졌고, 너무 복잡해졌다.

돌이켜 보면 한 사람이 동시에 굴리기에는 붙어 있는 것이 너무 많았다.
기물 움직임을 정의하는 언어, 그 언어로 만든 페어리 기물들,
게임 도중 판을 바꾸는 카드, 보드 크기 가변, 기물을 만드는 스튜디오,
아이콘 자동 채색, 로그인과 공유까지 — 하나하나는 다 재미있어서 붙였는데
전부 서로 맞물려 있어서 한 곳을 건드리면 다른 곳이 흔들렸다.

새 기능을 넣으려면 먼저 예전에 짠 것을 다시 이해해야 하는 상태가 됐고,
그러다 보니 손이 안 갔다.
